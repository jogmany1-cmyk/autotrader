## 3. 이 세션에서 고친 것

### 3-1. `edge`가 지표 캐시를 쓰지 않아 봉 수의 제곱으로 느렸다 (`5a8c9f6`)

**발견 경위**: 사용자가 `Measure-Command`로 3종목 39.79초를 실측 →
4,298종목 환산 **약 15.8시간**. 그냥 기다렸다면 밤새 돌다 아침에도 안 끝났을 것.

**원인**: `Backtester`는 종목별 `indicator_cache`를 `StrategyContext`에 넘기는데
(`backtest.py:223`), `EdgeAnalyzer.run`만 캐시 없이 컨텍스트를 만들고 있었다.
전략이 매 봉마다 `[0..at]` 전체에 대해 지표를 다시 계산했다.

**증상이 조용했다.** 값은 정확히 같고 느리기만 하다. 테스트도 리포트도 불평하지
않았고, 실데이터에서 사람이 시간을 재보고서야 드러났다.

**수정**: 종목 루프에 `cache: Dict = {}`를 만들어 `StrategyContext(..., cache=cache)`로 전달.

**검증**:
- 합성 1,200봉 **8.76초 → 0.39초 (22.6배)**
- 출력 `diff` **완전 일치** (한 글자도 안 바뀜)
- 회귀 테스트 2개 추가 — 수정을 되돌리면 실패 확인 (`atr 1,990회 계산 / 평가 봉 528개`)

값이 같은 근거는 **인과성**이다. 지표들은 index `i`의 값이 `i` 이하 데이터만
쓰므로 전체를 한 번 계산해 `[at]`을 읽은 값과 앞부분만 잘라 계산한 마지막 값이
정확히 같다(`tests/test_indicator_cache.py`가 고정). **미래 정보 금지 규칙을
건드리지 않는다.**

### 3-2. `edge --strategy` — 격리 측정 (`fa6c70c`)

**왜**: 앙상블 전체가 지고 있을 때 "누가 주범인가"는 합친 숫자로 답이 안 나온다.
이기는 전략의 우위를 지는 전략이 덮어 쓴다.

**구현**: `Ensemble`이 `weights`를 `strat.name`으로 찾으므로(`ensemble.py:41`)
전략 목록만 걸러내면 격리가 된다.

```powershell
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --strategy swing_trend
```

**주의**: 점수는 남은 전략들의 가중평균이라 **하나만 남기면 점수 = 그 전략의
strength**가 된다. 따라서 격리 측정의 `--threshold`는 전체 앙상블에서의 같은
값과 뜻이 다르다. 리포트 머리에 `[격리]` 표시와 경고를 찍고, 참여 전략을
`EdgeReport.strategies`로 JSON에도 남긴다.

**검증**: 전체 381개 테스트 통과, 옵션 미사용 시 기존 출력과 `diff` 일치,
전략 이름 오타는 종료코드 2로 실패.

> 작업 중 기존 테스트 8개를 깨뜨렸다. `EdgeAnalyzer.ensemble`이 `evaluate()`
> 하나만 요구하는 느슨한 자리라는 것을 `_StubEnsemble`이 이미 고정하고 있었는데
> 그 인터페이스를 좁혔기 때문. **테스트를 고치는 대신 코드를 `getattr`로
> 되돌렸다** — 테스트가 지키던 것이 옳았다.

## 4. 보안 사고

터미널에 환경변수를 직접 입력하는 방식 때문에 **키움 실전 앱키·시크릿이
스크린샷에 노출**됐다. 재발급 조치.

**재발 방지 — Windows 사용자 환경변수에 영구 등록:**

```powershell
[Environment]::SetEnvironmentVariable('KIWOOM_APP_KEY',    '키',       'User')
[Environment]::SetEnvironmentVariable('KIWOOM_APP_SECRET', '시크릿',   'User')
[Environment]::SetEnvironmentVariable('KIWOOM_ACCOUNT_NUMBER', '계좌', 'User')
```

- 등록 후 **PowerShell 창을 닫고 새로 열어야** 적용된다
- 확인은 값이 아니라 길이로: `$env:KIWOOM_APP_KEY.Length`
- **`KIWOOM_MODE`는 영구 등록하지 않는다.** 기본값이 `paper`이고
  (`config.py:164`), `real`로 박아두면 모든 명령이 실전 서버를 향하게 된다.
  실전이 필요할 때만 `--real`을 손으로 붙인다

> `.env` 파일 방식은 이 저장소에서 동작하지 않는다. `.gitignore`에 등록은 돼
> 있으나 `.env`를 읽는 로더가 코드에 없다(`os.getenv`만 사용).

### 외부 데이터에 대한 판단 (과제 6)

데이터를 더 넣는다고 좋아진다는 보장은 없고, **오히려 나빠지기 쉽다.**
파라미터가 늘면 과거 성적을 아름답게 만들기는 쉬워지지만 실전에서 재현되지 않는다.

붙인다면 **싸고 안전한 것부터, 하나씩, 넣을 때마다 `edge`로 재면서**:

1. **시장 지수(KOSPI/KOSDAQ)** — 가장 가성비 높음. "시장이 하락 추세면 매수 금지"
2. **전날 미국장(나스닥/S&P)** — 한국장 시가에 직접 영향
3. 업종 지수 · 환율
4. **뉴스·공시(LLM) — 맨 마지막.** 미래 정보 누수(소급 수정된 뉴스 DB),
   재현 불가(같은 뉴스에 매번 다른 점수), 비용 세 가지가 겹친다

## 6. 다음 단계

**진행 중**: 전략 5개를 하나씩 격리 측정 (`edge --strategy`)

```powershell
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --strategy day_breakout   --output e_breakout.json
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --strategy day_pullback   --output e_pullback.json
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --strategy day_momentum   --output e_momentum.json
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --strategy swing_trend    --output e_swing.json
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --strategy mean_reversion --output e_meanrev.json
```

결과에 따라 갈리는 세 갈래:

| 그림 | 다음 수 |
|---|---|
| 한 전략만 확실히 마이너스 | 그 전략 가중치를 0으로 → 즉시 개선 |
| 전부 t값 0 근처 | 개별 전략이 아니라 **합치는 방식**(가중치·투표)이 문제 |
| 한둘은 플러스인데 전체는 마이너스 | 좋은 전략이 나쁜 전략에 묻히고 있음 |

### 하지 말아야 할 것

**`--threshold`를 바꿔가며 플러스가 나오는 값 찾기.** 지평선 4개 × 임계값 여러
개를 다 돌리면 그중 하나는 반드시 좋아 보인다 — 전부 잡음이어도 그렇다.
`edge.py`의 `best_t()`에도 같은 경고가 달려 있다.

지금 결과상 **점수가 높을수록 나쁘므로 임계값을 올리면 오히려 악화된다.**

## 7. 재현용 명령 모음

```powershell
# 0. 자격증명 (한 번만, 새 창에서 적용)
[Environment]::SetEnvironmentVariable('KIWOOM_APP_KEY', '키', 'User')

# 1. 수집
python -m autotrader fetch --real --cache data/kiwoom --limit 3000

# 2. 무결성 게이트 (백테스트 구간과 --bars 를 맞출 것)
python -m autotrader --csv data/kiwoom validate-data --bars 2500 --jump-pct 0.31 --output quality2.json

# 3. 진입 신호 우위
python -m autotrader --csv data/kiwoom --threshold 0.45 edge --bars 2500 --output edge.json

# 4. 백테스트
python -m autotrader --csv data/kiwoom --threshold 0.45 backtest --bars 2500 --output backtest.json

# 5. 승인 판정
python -m autotrader validate --registry runs/registry.json
```

**전역 옵션(`--csv` `--threshold` `--config` `--votes` `--trail`)은 하위 명령
앞에 쓴다.** 특히 `--csv`를 빠뜨리면 **합성 데이터를 검사해놓고 통과했다고
착각하게 된다**(`cli.py:277`).

## 8. 이 세션이 남긴 교훈

1. **조용한 실패가 가장 비싸다.** `edge` 성능 버그는 값이 정확하고 느리기만
   해서 테스트도 리포트도 불평하지 않았다. 사람이 시간을 재보지 않았으면 못
   찾았다. → 회귀 테스트로 고정했다.

2. **판정 문구를 그대로 믿지 않는다.** 무결성 검사가 "FAIL, 원본을 고치거나
   다시 수집하세요"라고 했지만, 실제로는 4,298종목 중 1종목의 12년 전 5봉
   문제였다. 집계만 보고 재수집했다면 헛수고였다.

3. **가설은 데이터로 폐기한다.** "유량 제한" 가설은 4,298개 성공이라는 사실
   하나로 무너졌다. 추측을 사실처럼 말하지 않는다.

4. **나쁜 결과도 성과다.** 진입 신호에 우위가 없다는 것을 **실제 돈이 아니라
   계산으로** 알아냈다. 승격 경로와 게이트가 설계대로 작동했다.
