# Walk-forward 비교 규격 (실행 전 고정)

**확정일: 2026-08-25 · 실행 전 합의 · 결과를 본 뒤 수정 금지**

이 문서는 앙상블 점수 방식 3안을 같은 조건에서 비교하기 위한 규격이다.
코드로도 못박혀 있다 — `autotrader/walkforward.py`, `tests/test_walkforward_spec.py`.
값을 바꾸면 테스트가 실패한다.

---

## ⚠️ 이 규격의 지위 — 먼저 읽을 것

**이 walk-forward 는 확증이 아니라 탐색 검증이다.**

2,500봉 전체 결과(`edge`·`backtest`)를 이미 본 뒤에 설계됐다. 같은 데이터에서
변형을 여러 개 비교할수록 백테스트 과최적화 위험이 커진다
([Bailey et al., *The Probability of Backtest Overfitting*](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2308659)).

**이 규격을 통과해도 실전 승격 근거가 되지 않는다.** 승격에는 별도로 필요하다:

1. 이후 새로 수집되는 **미사용 데이터**
2. 최소 **60거래일 페이퍼 트레이딩**
3. 사람의 명시적 승인 (`CLAUDE.md` — AI 는 승격을 권고만 할 수 있다)

---

## 1. 배치 — expanding train

시작점은 1일로 고정, 끝점만 250일씩 확장. **2,500봉에서 정확히 4 fold.**

| Fold | Train | Purge | Validation | Purge | OOS |
|---|---|---|---|---|---|
| 1 | 1–1000 | 1001–1020 | 1021–1270 | 1271–1290 | **1291–1540** |
| 2 | 1–1250 | 1251–1270 | 1271–1520 | 1521–1540 | **1541–1790** |
| 3 | 1–1500 | 1501–1520 | 1521–1770 | 1771–1790 | **1791–2040** |
| 4 | 1–1750 | 1751–1770 | 1771–2020 | 2021–2040 | **2041–2290** |

봉 번호는 1부터 시작하는 닫힌 구간.

| 파라미터 | 값 |
|---|---|
| TRAIN 최소 길이 | 1,000 거래일 |
| VALIDATION | 250일 |
| OOS | 250일 |
| 이동 폭 | 250일 |
| 경계 purge | 20일 (**양쪽 경계 모두**) |

### 자투리 210봉은 버린다

`2291–2500` 의 210봉은 고정 250일 OOS 조건을 충족하지 못하므로 **채점에서
제외**한다. 짧은 다섯 번째 fold 를 임의로 만들지 않는다 — 표본이 작아 판정이
흔들리고, "몇 개까지 만들지" 가 결과를 보고 정하는 손잡이가 된다.

리포트에 제외 구간을 명시한다. 조용히 버리면 "전 구간을 썼다"고 오해하게 된다.

## 2. 불변조건

| # | 조건 |
|---|---|
| 1 | 각 평가 구간은 **포지션 없이 시작** |
| 2 | 이전 구간의 포지션을 다음 구간으로 **이월하지 않음** |
| 3 | purge 구간에서 **신규 진입 금지** |
| 4 | 지표 계산에는 이전 데이터 **사용 가능** (인과성 유지) |
| 5 | purge 구간의 성과와 거래는 **채점에서 제외** |

### purge 가 필요한 이유

20봉 보유 전략은 구간 경계를 넘는다. 경계를 붙여 놓으면 TRAIN 마지막 날 진입한
포지션의 결과가 VALIDATION 에 실려 두 구간이 정보를 공유한다.

## 3. 고정 설정 — 실행 후 재조정 금지

```
--threshold 0.45
min_votes   1
비용         Costs 기본값 (commission 1.5bp 편도 / tax 18bp 매도 / slippage 5bp 편도)
데이터       data/kiwoom, 최근 2,500봉
```

**실행 후 임계값·가중치를 조정하고 다시 돌리는 것을 금지한다.** 그렇게 얻은
결과는 검증이 아니라 탐색이다.

---

## 4. 채점

### 합산 OOS PF — 풀링이지 평균이 아니다

```
합산 PF = Σ(모든 fold 의 총이익) / Σ(모든 fold 의 총손실)
```

fold 별 PF 의 **단순 평균이 아니다.** 평균을 쓰면 거래 두 건짜리 fold 가
200건짜리 fold 와 같은 무게를 갖고, 손실이 0 인 fold 하나가 무한대로 평균을
오염시킨다.

### PnL 정의

**수수료·거래세·슬리피지가 모두 반영된 체결 기준.** 슬리피지는 `PaperBroker` 가
체결가에 반영하므로 PnL 에 이미 들어 있다 — 감사 리포트에서 다시 빼지 않는다
(이중 차감 금지, `tests/test_cost_audit_slippage.py` 가 고정).

### 안정성 (집중도)

```
fold_gross_profit = 해당 OOS fold 에서 양수 PnL 의 합
concentration     = max(fold_gross_profit) / Σ(all fold_gross_profit)
```

- `concentration > 0.50` → **안정성 실패**
- 전체 gross profit 이 0 이면 → **자동 실패**
- 순이익이나 비용 전 수익을 분모로 쓰지 않음
- **PF 의 분자와 같은 정의**를 사용

## 5. 판정 기준 — 기존 승격 기준을 낮추지 않는다

| # | 기준 |
|---|---|
| 1 | 합산 OOS Profit Factor ≥ **1.20** |
| 2 | 합산 OOS 순수익 **> 0** |
| 3 | Max Drawdown ≥ **-25%** |
| 4 | 합산 거래 ≥ **100** |
| 5 | 각 OOS fold 거래 ≥ **20** |
| 6 | 4개 OOS 중 최소 **3개에서 PF > 1.0** |
| 7 | 집중도 ≤ **0.50** |

기준 1 은 `registry.ValidationThresholds.min_oos_profit_factor` 와 같은 값이며,
테스트가 두 값의 일치를 고정한다.

**전부 충족해야 통과.** 하나라도 미달이면 실패다.

## 6. 비교 대상 3안

| 안 | 내용 | 비고 |
|---|---|---|
| `all-weights` | 현재 방식 (분모 = 모든 활성 전략 가중치) | **기본값** |
| `active-voters` | 분모 = 신호를 낸 전략의 가중치 | 실험 옵션 |
| 독립 전략 | mean_reversion 5봉 / swing_trend 20봉 / day_momentum 20봉 **각각 별도 실행** | |

### `active-voters` 해석 규칙 (결과 확인 전 사전 등록)

`active-voters`에서도 `threshold=0.45`, `min_votes=1`을 그대로 사용한다.
BUY 표가 하나뿐이면 분자와 분모에 같은 전략 가중치가 들어가므로 최종 점수는
그 전략의 strength와 같다. 따라서 단일 전략의 strength가 0.45 이상이면
통과한다. `min_votes`를 2 이상으로 올려 거래 수를 맞추거나, 두 모드의 임계값을
서로 다르게 조정하지 않는다. 결과를 본 뒤 그런 값을 고르는 것은 별도 탐색이다.

이 때문에 두 모드는 같은 거래 빈도를 맞춘 대조군이 아니다. 격리 측정에서
`swing_trend` 신호율만 21.13%였으므로, 전략 간 신호 중복을 감안하더라도
`active-voters` 신호율은 사전 예상으로 20% 이상(대략 20~25%),
`all-weights` 실측 0.33%보다 훨씬 높을 가능성이 있다. 이 범위는 판정 기준이 아니라 검증할
가설이다. 결과는 “어느 점수 공식이 같은 거래를 더 잘 고르는가”가 아니라
**거래 빈도와 비용까지 포함해 서로 다른 두 진입 시스템이 어떻게 작동하는가**로
해석한다.

전략별 strength 원척도도 그대로 둔다. 상한은 `day_breakout=0.95`,
`day_pullback=0.90`, `day_momentum=0.90`, `swing_trend=0.95`,
`mean_reversion=0.70`이다. 전략별 상한으로 재정규화하지 않는다. 따라서
`active-voters`에서 전략별 점수 범위가 다르며, 특히 `mean_reversion`의
최대 점수는 0.70이다. 정규화 버전은 이번 비교에 포함하지 않는 별도 전략으로
취급하며, 필요하면 결과를 보기 전에 새 규격으로 등록한다.

### 독립 전략 규칙 (결과 확인 전 사전 등록)

**`5봉/20봉`은 "우위가 관측된 지평선"이 아니라 실제 최대 보유기간이다.**
`edge` 에서 우위가 보였던 지평선을 그대로 강제청산 상한으로 쓴다.

| 전략 | 최대 보유 | `edge` 에서 우위가 보였던 지평선 |
|---|---|---|
| `mean_reversion` | **5봉** | 1일 t=+15.98 · 5일 t=+5.05 |
| `swing_trend` | **20봉** | 5·10·20일 t=+5.46 / +6.29 / +4.34 |
| `day_momentum` | **20봉** | 10·20일 t=+3.08 / +2.93 |

적용 방식:

- 기존 **손절·목표가·트레일링 청산은 그대로 유지**한다. 최대 보유기간은
  그 위에 얹는 **상한**이지 유일한 청산 규칙이 아니다.
- 전략별 **단독 실행**. 자본은 각각 동일하게 초기화한다.
- 비용 · fold · `threshold=0.45` · `min_votes=1` 은 앙상블 두 모드와 **동일**.
- 세 결과를 합쳐 포트폴리오처럼 평가하지 **않는다**.

**왜 이 방식인가.** 손절 없이 정확히 5/20봉 종가에만 청산하면 `edge` 측정과는
가까워지지만, 기존 위험관리를 들어낸 **다른 전략**이 된다. 이 비교의 목적은
"실전에 올릴 수 있는 형태끼리" 견주는 것이므로 위험관리를 유지한다. 순수
지평선 청산 버전이 필요하면 **별도 규격으로 새로 등록**한다.

`max_holding_bars` 는 실행마다 그 전략 값으로 덮어쓰며, 리포트에 실제 사용값을
남긴다. 기본 설정(20봉)이 조용히 쓰이면 `mean_reversion` 이 5봉 전략이
아니게 되는데, 리포트만 보고는 알 수 없다.

### 처음부터 합치지 않는다

먼저 각각의 결과와 **상관관계**를 확인한 뒤 자본 배분 규칙을 **사전 등록**한다.
서로 다른 지평선에서 우위가 있다는 것과 포트폴리오 분산 효과가 있다는 것은
별개다 — 후자는 아직 입증되지 않았다.

### 실행할 다섯 가지

```
1. all-weights                      (앙상블, 현재 방식)
2. active-voters                    (앙상블, 실험)
3. mean_reversion  단독 · 최대 5봉
4. swing_trend     단독 · 최대 20봉
5. day_momentum    단독 · 최대 20봉
```

다섯 실행은 **같은 fold · 같은 비용 · 같은 임계값**을 쓴다. 결과를 본 뒤
대상을 추가하거나 빼지 않는다 — 그 선택 자체가 사후 편향이다.

## 7. 저장할 것

- fold 별 성과 + 합산 성과 **양쪽 모두**
- 각 fold 의 거래 수·총이익·총손실 (합산 PF 재계산 가능해야 함)
- 비용 감사 (`cost_audit`) — 회전율·비용이 다른 두 실행이 같은 조건으로
  오해되지 않도록
- 제외된 자투리 구간
- 실행에 쓴 설정 전체 (threshold, min_votes, 비용, score-mode)
- OOS 거래 진단: 승률·평균/중앙 손익·평균 승/패·payoff ratio·평균/중앙
  보유기간·청산 사유별 성과·청산 연도별 성과
- 비용 차감 후 순손익, 총비용, 비용 전 **추정** 순손익. 비용 전 값은
  슬리피지 추정치를 되더한 진단값이며 성과에 다시 반영하지 않는다.
- 진입 흐름: 전략 평가 수, 매수 신호 수·비율, 다음 봉 주문 시도, 실제 체결,
  리스크 거절 사유. 이는 진입·청산 규칙을 바꾸지 않는 감사 계수다.
- 포지션 자리가 부족할 때 후보는 **점수 내림차순, 동점은 종목코드 오름차순**으로
  선택한다. 입력 파일·유니버스 순서는 매매 결과에 영향을 주면 안 된다.
- 완료 거래에 진입 점수·투표 수를 보존하고, 고정 0.1 점수 구간별 성과를 남긴다.
